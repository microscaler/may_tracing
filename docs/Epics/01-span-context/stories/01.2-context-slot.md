# Story 01.2: The context slot — `current()` on coroutines and threads

## Description

The storage that makes everything else work: one slot per **coroutine** holding a
`tracing::Span` handle, and one per **native thread** for code that is not inside a
coroutine. `current()` reads whichever applies. The slot is private; the only way to
write it is 01.3's `set_current`. This story proves the load-bearing assumption of
ADR-0002 — that `may::coroutine_local!` storage moves with the coroutine when the
scheduler resumes it on another OS thread — before anything is built on it.

## Functional Requirements

- [ ] `src/context.rs`:
  - `may::coroutine_local!(static CURRENT: RefCell<Span> = RefCell::new(Span::none()));`
  - `thread_local!(static CURRENT_THREAD: RefCell<Span> = RefCell::new(Span::none()));`
  - `pub(crate) fn with_slot<R>(f: impl FnOnce(&RefCell<Span>) -> R) -> R` choosing the
    coroutine slot when `may::coroutine::is_coroutine()` is true, else the thread slot
- [ ] `pub fn current() -> Span` — a clone of the slot's span (`Span::none()` when unset)
- [ ] `pub fn is_in_coroutine() -> bool` re-exported for callers that want to know which
      slot applies (thin wrapper over may's `is_coroutine`)
- [ ] `Span::none()` is the empty state — no `Option`, so `current()` is always usable as a
      `parent:` and `.is_none()` is the "no context" test
- [ ] The `RefCell` borrow is never held across a call into user code (read-clone-release)

## Non-Functional Requirements

- [ ] `current()` costs one TLS/coroutine-local lookup and one `Span::clone` (an `Arc`
      increment on an enabled span, nothing on a disabled one); no allocation
- [ ] No `unsafe`
- [ ] Works when no `tracing` subscriber is installed (`Span::none()` throughout)
- [ ] Works inside `may::go!` coroutines spawned by consumers before this crate was ever
      touched (lazy init of the coroutine-local on first access)

## Acceptance Criteria

1. `current()` on a fresh coroutine and on a fresh thread returns a span with `is_none()`
2. A value written to the coroutine slot (via a `pub(crate)` test hook) is read back by the
   same coroutine after it has yielded and been resumed on a **different** OS thread
3. Two coroutines on the same worker thread never see each other's slot
4. A native thread's slot is independent of every coroutine's
5. The `RefCell` is never double-borrowed: reading `current()` from inside a closure that
   already holds the slot is impossible by construction (`with_slot` is not re-entrant
   and is not public)

## Tests

```rust
// tests/slot.rs
use std::sync::atomic::{AtomicUsize, Ordering};

#[test]
fn fresh_contexts_are_none() {
    assert!(may_tracing::current().is_none());
    let h = unsafe { may::coroutine::spawn(|| may_tracing::current().is_none()) };
    assert!(h.join().unwrap());
}

/// The migration test: 200 coroutines on 4 workers, each sets its own span, yields a
/// few hundred times, and checks after every yield that current() is still its own.
#[test]
fn slot_travels_with_the_coroutine_across_workers() {
    may::config().set_workers(4);
    let subscriber = tracing_subscriber::registry();
    let _g = tracing::subscriber::set_default(subscriber);
    let bad = std::sync::Arc::new(AtomicUsize::new(0));
    let hs: Vec<_> = (0..200).map(|i| {
        let bad = bad.clone();
        unsafe { may::coroutine::spawn(move || {
            let mine = tracing::info_span!("co", i);
            let _ctx = may_tracing::set_current(mine.clone());   // 01.3; use the test hook until then
            for _ in 0..300 {
                may::coroutine::yield_now();
                if may_tracing::current().id() != mine.id() { bad.fetch_add(1, Ordering::Relaxed); }
            }
        }) }
    }).collect();
    for h in hs { h.join().unwrap(); }
    assert_eq!(bad.load(Ordering::Relaxed), 0);
}

#[test]
fn thread_slot_is_independent() {
    let t = std::thread::spawn(|| { /* set on this thread, assert visible, return */ });
    t.join().unwrap();
    assert!(may_tracing::current().is_none());   // main thread untouched
}
```

Assert in the migration test that the coroutines really did migrate: record
`std::thread::current().id()` before and after each yield and require at least one
change across the run, otherwise the test proves nothing (guard against a single-worker
config leaking in).

## Notes

- If `may::coroutine::is_coroutine()` turns out not to be public in 0.3.51, the fork
  exposes it (one-line change) — record in the story what was done. Do not cache the
  answer: a native thread can call into code that later runs in a coroutine.
- `coroutine_local!` values are dropped with the coroutine; the `Span` handle therefore
  cannot outlive the coroutine that holds it, which is the invariant the Risks table
  relies on.
