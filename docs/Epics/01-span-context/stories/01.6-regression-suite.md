# Story 01.6: The regression suite — migration under load, the ADR-0001 reproduction

## Description

The tests that justify the crate's existence, kept separate so nobody trims them as
"slow": (a) the coroutine-migration soak from 01.2 turned into a longer, multi-worker,
mixed-workload run; (b) a faithful reproduction of the production failure — a span
**entered** across a yield on a real `tracing_subscriber::Registry`, coroutines migrating,
and the resulting `tried to clone a span that already closed` panic — followed by the same
workload through `with_span` with zero panics; (c) an OTEL-shaped check that spans created
through the context carry the right parent ids end to end.

## Functional Requirements

- [ ] `tests/regression_adr0001.rs`, `#[ignore]`-free but bounded to ~2 s wall clock:
  - `entered_across_yield_panics_on_registry`: N=64 coroutines on 4 workers; each loops
    `{ let _e = info_span!("bad").entered(); may::coroutine::yield_now(); }` and then
    creates a child `info_span!("probe")`; run under `catch_unwind` per coroutine; assert
    **at least one** coroutine panicked with a message containing
    `"tried to clone a span"` or `"already closed"`. If the assertion is flaky (the race is
    real but probabilistic), raise N and iterations until it fails deterministically on
    both CI hosts, and record the numbers in the test.
  - `with_span_across_yield_never_panics`: the identical workload with
    `with_span(info_span!("good"), || yield_now())` and `child_span!` for the probe; assert
    zero panics and that every probe's parent is its coroutine's span.
- [ ] `tests/soak.rs` (`#[ignore]` by default; `cargo test -- --ignored` in CI's nightly
      job): 500 coroutines, 8 workers, 10 s, each alternating `child_span!`, an event, a
      spawn-with-context of a short child, and yields; assert zero context mismatches and
      zero panics; print thread-migration count as evidence
- [ ] `tests/support/mod.rs`: the recording `Layer` from 01.5 plus a
      `MigrationCounter` helper (thread id before/after each yield)
- [ ] The regression test file carries a header comment naming the incident
      (PriceWhisperer US_37_08, 20 Sep 2026) and ADR-0001, and the sentence "This test must
      never be deleted; if it stops failing in the `bad` case, tracing-subscriber changed and
      ADR-0001 needs re-reading."

## Non-Functional Requirements

- [ ] The `bad` reproduction runs inside `catch_unwind` per coroutine so a panic never
      aborts the test process; may's join reports the panic
- [ ] Both tests set their own `Registry` via `set_default` (thread-scoped) — no global
      subscriber, so the rest of the suite is unaffected
- [ ] Deterministic on `ubuntu-latest` and `macos-latest` runners (CI runs each 3×)

## Acceptance Criteria

1. `entered_across_yield_panics_on_registry` fails the *inner* workload (panics observed)
   and passes as a test, on both CI hosts, 3 runs each
2. `with_span_across_yield_never_panics` passes with 0 panics and 0 parent mismatches
3. The soak test passes when run with `--ignored` and reports > 0 thread migrations
4. Removing the `parent:` from `child_span!`'s expansion (a deliberate local sabotage)
   makes test 2's parent assertion fail — the suite detects the regression it is for

## Definition of Done

- [ ] CI: the two regression tests in the default job; the soak in a scheduled nightly
      job (`workflow_dispatch` + cron)
- [ ] Numbers (N, iterations, observed panic rate) recorded in the test header
- [ ] `docs/Design.md` §8 updated with what was actually needed to make the `bad` case
      deterministic
- [ ] Commit message: `test: ADR-0001 reproduction and migration soak (Epic 01.6)`

## Tests

The story *is* the tests; the shape:

```rust
fn workload(good: bool, n: usize, iters: usize) -> (usize /*panics*/, usize /*mismatches*/) {
    may::config().set_workers(4);
    let _s = tracing::subscriber::set_default(tracing_subscriber::registry().with(recorder));
    let hs: Vec<_> = (0..n).map(|i| unsafe { may::coroutine::spawn(move || {
        std::panic::catch_unwind(|| {
            for _ in 0..iters {
                if good {
                    let s = tracing::info_span!("good", i);
                    may_tracing::with_span(s.clone(), || { may::coroutine::yield_now(); let _p = may_tracing::child_span!(tracing::Level::INFO, "probe"); });
                } else {
                    let _e = tracing::info_span!("bad", i).entered();
                    may::coroutine::yield_now();
                    let _p = tracing::info_span!("probe");   // parented on the thread's current: the trap
                }
            }
        }).is_err()
    }) }).collect();
    (hs.into_iter().filter(|h| h.join().unwrap_or(true)).count(), recorder.mismatches())
}
```

## Notes

- The panic in the `bad` case comes from `tracing_subscriber::registry::sharded` asserting
  in `clone_span`. If a future tracing-subscriber turns that into a silent no-op, the
  `bad` test will "fail to fail" — that is information, not a reason to weaken the test.
- Keep runtimes short; the soak is the place for long runs.
