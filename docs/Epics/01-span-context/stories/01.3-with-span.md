# Story 01.3: `with_span` / `set_current` / `ContextGuard`

## Description

The only writers of the slot. `set_current(span)` swaps the slot and returns a guard that
restores the previous value on drop; `with_span(span, f)` is the closure form. Neither
touches any thread's span stack — a `ContextGuard` is not an `Entered`, and the docs must
say so in the first sentence. The guard is what makes nesting and unwinding correct: LIFO
restore, and restore during panic unwinding.

## Functional Requirements

- [ ] `pub struct ContextGuard { prev: Option<Span> }` — `#[must_use = "dropping the guard restores the previous span immediately"]`,
      not `Clone`, not `Send` (it belongs to the coroutine/thread that created it; document why)
- [ ] `pub fn set_current(span: Span) -> ContextGuard` — `std::mem::replace` on the slot
- [ ] `impl Drop for ContextGuard` — writes `prev` back; idempotent (`prev.take()`)
- [ ] `pub fn with_span<R>(span: Span, f: impl FnOnce() -> R) -> R` — `let _g = set_current(span); f()`
- [ ] `pub fn with_none<R>(f: impl FnOnce() -> R) -> R` — sugar for `with_span(Span::none(), f)`;
      used by `spawn_detached` and by code that must not attribute a section (a pool worker)
- [ ] Rustdoc on `ContextGuard` states: "Holding the guard keeps the span *open* (a handle),
      not *entered*; nothing is pushed on any thread's span stack. Dropping it does not close
      the span; the span closes when its last handle is dropped."

## Non-Functional Requirements

- [ ] Unwind safety: a panic inside `f` restores the slot before the panic propagates
      (verified with `catch_unwind` in tests)
- [ ] Re-entrancy: nested `set_current` calls restore in LIFO order regardless of the
      order the guards are dropped in the source (document that dropping out of order is a
      bug in the caller and what happens: the outer guard's restore wins)
- [ ] Cost: one slot swap per call; no allocation
- [ ] Sending a `ContextGuard` to another coroutine is a compile error (`!Send` via a
      `PhantomData<*const ()>` field or `impl !Send` on nightly — use the `PhantomData`)

## Acceptance Criteria

1. `with_span(a, || current().id()) == a.id()` and `current()` is back to the previous value afterwards
2. `with_span(a, || with_span(b, || current()))` yields `b` inside, `a` between, previous after
3. A panic inside `with_span` leaves `current()` at the previous value (caught with `catch_unwind`)
4. `set_current` from a native thread affects only that thread's slot; from a coroutine only that coroutine's
5. The guard is `!Send` (a `compile_fail` doctest)
6. `with_none` inside `with_span(a, …)` reads `Span::none()`, and `a` is back afterwards

## Tests

```rust
// tests/with_span.rs
#[test]
fn nests_and_restores() {
    let _s = tracing::subscriber::set_default(tracing_subscriber::registry());
    let a = tracing::info_span!("a"); let b = tracing::info_span!("b");
    assert!(may_tracing::current().is_none());
    may_tracing::with_span(a.clone(), || {
        assert_eq!(may_tracing::current().id(), a.id());
        may_tracing::with_span(b.clone(), || assert_eq!(may_tracing::current().id(), b.id()));
        assert_eq!(may_tracing::current().id(), a.id());
    });
    assert!(may_tracing::current().is_none());
}

#[test]
fn restores_on_unwind() {
    let _s = tracing::subscriber::set_default(tracing_subscriber::registry());
    let a = tracing::info_span!("a");
    let r = std::panic::catch_unwind(|| may_tracing::with_span(a, || panic!("boom")));
    assert!(r.is_err());
    assert!(may_tracing::current().is_none());
}
