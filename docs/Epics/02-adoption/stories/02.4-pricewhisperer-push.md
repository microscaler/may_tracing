# Story 02.4: pricewhisperer_push — stream loops and ticks under the opening request; the load-run acceptance

**Repo:** microscaler/PriceWhisperer (`microservices/pricewhisperer_push`, the three
`get_*_stream.rs` handlers)

## Description

The push streams are the one place with long-lived coroutines spawned from a handler, and
the place the ADR-0001 panic was found. Spawn the stream loop with the request context,
give each tick a `push.tick` span that the tail query nests under, turn the loop's
lifecycle prints into events on the request span, and run the 200 × 40 load test as the
acceptance for the whole epic.

## Functional Requirements

- [ ] `get_market_stream.rs`, `get_alerts_stream.rs`, `get_orders_stream.rs`: the
      `may::coroutine::Builder … .spawn(…)` becomes `.spawn_with_context(…)` (`BuilderExt`)
- [ ] `StreamLoop::run_inner`: per tick,
      `let tick = may_tracing::child_span!(Level::DEBUG, "push.tick", topic = topic.as_str());`
      `let res = may_tracing::with_span(tick, || catch_unwind(… self.source.next(…)))`
      — the tick span is the context for the query so lifeguard nests under it; it closes
      when `res` is back
- [ ] `[push] … stream closed: reason=…` and the tick-failure `eprintln!`s become
      `may_tracing::info_in_current!` / `warn_in_current!` with the same text (keep the
      `eprintln!` too until the OpenSearch monitor for stream closes exists — they are what
      `kubectl logs` shows)
- [ ] The listener coroutine (`listener::Listener::spawn`) stays detached — it is
      process-scoped; add `spawn_detached` explicitly so the choice is visible
- [ ] `hello`/`bye` remain as they are on the wire; nothing client-visible changes

## Non-Functional Requirements

- [ ] Per-tick overhead: one `child_span!` (a disabled span when the DEBUG level is
      filtered out at the subscriber — verify the level filter in the services' tracing
      config so ticks are not exported at INFO by default; 300 streams × 1.2 ticks/s of
      exported spans would be its own problem)
- [ ] `catch_unwind` stays; `pw_stream_tick_failures_total` must read 0 after the change

## Acceptance Criteria

1. Trace of a `/orders/stream` request in OpenSearch: `http_request` → `push.tick` →
   `lifeguard.execute_query` (with the DEBUG filter lifted for the check)
2. `scripts/load/streams.py --conns 200 --symbols 40 --minutes 10` after 16:00 ET:
   `drops 0`, `gaps 0`, `pw_stream_tick_failures_total` delta 0, market pod restarts 0,
   REST p95 delta ≤ +10 ms — recorded as a second table in
   `docs/Architecture/Push-Streams-Listen-Notify.md` §6.1
3. Same run at 300 × 40 on the 1 vCPU market limit (90618858): completes; number recorded
   (this is the first time 300 has a chance to pass)
4. `kubectl logs` for a stream open/close unchanged in content
