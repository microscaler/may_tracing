# Story 02.2: lifeguard — spans are children of the coroutine context; nesting default on

**Repo:** microscaler/lifeguard

## Description

lifeguard's `tracing_helpers` create root spans (c9673d7) with an off-by-default switch
to link to the thread's current span (9e5f12d). Replace the thread-local read with
`may_tracing::current()`, which is safe on may, and flip the default to nested. Call sites
stay "created, not entered". Pool worker coroutines are explicitly detached.

## Functional Requirements

- [ ] `may_tracing = { git = …, tag = "v0.1.0" }` (non-optional: lifeguard is may-only)
- [ ] `metrics::tracing_helpers`: each helper becomes
      `if span_nesting() { may_tracing::child_span!(Level::INFO, "lifeguard.<op>", …) } else { span!(parent: None, …) }`
      — the macro form, so `%query` forwards (the hand-written `execute_query_span` branch
      from 9e5f12d goes away)
- [ ] `span_nesting()` default → `true`; `LIFEGUARD_SPAN_NESTING=0|false|off` turns it off;
      `set_span_nesting(false)` still works; docs updated: "nesting reads the coroutine
      context (may_tracing), never the thread's current span, and is safe on may"
- [ ] Pool worker coroutines (`pool/pooled.rs`, the per-connection workers) spawned via
      `may_tracing::spawn_detached` (or `with_none` at the top of the worker body if the
      spawn site is may's `go!`), with a comment: the query span is created on the caller's
      coroutine; the worker's own events are pool-scoped
- [ ] Worker-side events (`pool_slot_heal`, keepalive, rotation) tagged with
      `pool_tier = …` since they no longer have a request parent

## Non-Functional Requirements

- [ ] Query hot path adds one `current()` read per span (one coroutine-local access, one
      `Arc` clone when a context exists)
- [ ] With `span_nesting()` off, behaviour is byte-identical to 9e5f12d
- [ ] `cargo test` (the whole lifeguard suite, 490+ tests) green; the `tracing_helpers`
      nesting test extended with a `may_tracing::with_span` case

## Acceptance Criteria

1. Under `with_span(a, …)`, `execute_query_span("select 1")` has parent `a` (recording layer)
2. With no context, it is a root span; with `LIFEGUARD_SPAN_NESTING=0`, always a root span
3. A worker coroutine's `pool_slot_heal_span()` is a root span even when the pool was
   created inside a request context
4. The PriceWhisperer 200 × 40 load run with 02.1 + this: 0 tick failures, 0 restarts,
   and `lifeguard.execute_query` nests under `http_request` in OpenSearch

## Tests

```rust
#[test]
fn query_span_nests_under_coroutine_context() {
    let (layer, rec) = /* recording layer */;
    let _s = tracing::subscriber::set_default(tracing_subscriber::registry().with(layer));
    let req = tracing::info_span!("http_request");
    let q = may_tracing::with_span(req.clone(), || tracing_helpers::execute_query_span("select 1"));
    assert_eq!(rec.parent_of(q.id().unwrap()), req.id());
}
```
